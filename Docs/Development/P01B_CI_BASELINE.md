# D01-03 · P01-B의 CI 보존 기준 수정

## 확인한 실패

커밋 da24b8627dbac1153f860b9cf3afe67b4a27b05d의 PR #2 검사 run 36611263754, job 109552981389가 기존 자산 보존 단계에서 실패했다. Python 시험과 정책 검사는 그 뒤라 실행되지 않았다.
기존 규칙은 초기 커밋 53f11e80ec32ba1caa4f7009bdb600db6c14755a 이후 모든 파일의 수정/삭제를 금지했다. 사용자가 직접 진행한 URP 변경과 Unity 준비 때문에 Packages/manifest.json, ProjectSettings/GraphicsSettings.asset, ProjectSettings/TagManager.asset이 이미 달라져 있었다.

P01-B의 비교 기준 c1308802f5051c4475c463739749d56acdf7257c에는 그 사용자 변경과 P01-A가 포함돼 있다. c130880에서 da24b862까지의 변경은 P01-B 소스·조립·시험·문서·도구이며, 위 세 파일을 수정하지 않았다. 옛 실패를 코드나 Unity 시험 성공으로 다시 표시하지 않는다.

## 적용한 규칙

보호 기준을 c1308802f5051c4475c463739749d56acdf7257c로 고정하고, Packages/ProjectSettings/기존 Assets/Git 정책/.vscode의 수정·삭제·이름/형식 변경을 검사한다. 프로젝트에서 새로 작성하는 Assets/_Game 및 해당 폴더 .meta는 기능 구현 범위이므로 별도 코드·데이터 검토 대상으로 둔다. 기준 커밋이 없으면 검사 자체가 실패한다.

임의 diff를 모두 허용하거나, 검사 실패를 성공으로 바꾸거나, 기존 파일을 기준값으로 되돌리지 않는다. 향후 보호 영역을 의도적으로 수정해야 할 때는 명시적인 변경·인수 기록과 함께 이 규칙을 검토한다. 추가 .meta를 생성했다고 기존 GUID를 바꿀 수 있는 것은 아니다.

Python 전체 도구 시험, P00 저장소 정책 감사는 유지한다. P01-A 원본 코어와 시험의 전달 해시 검사를 추가해 이번 어댑터 작업이 코어를 바꾸지 않았는지 검사한다. action 버전·토큰 권한·branch protection 설정은 변경하지 않는다.

## 완료 경계

이 변경은 잘못된 이식 전용 가정을 수정하는 CI 작업이다. 새로운 run의 실제 결과를 확인하기 전에는 통과라고 쓰지 않는다. CI가 통과하더라도 실제 Unity 어댑터 30개, 하드웨어 입출력 지연, Windows 빌드/시작/종료, EXIT-P01은 각각 별도 증거가 필요하다.
